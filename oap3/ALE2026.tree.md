# ALE2026 syntax graph (exported from ALE2026.vsdx)

State machine for the ALE (arithmetic/logic expression) grammar, extracted
from the Visio shapes + dynamic-connector links in `visio/pages/page1.xml`.

## States

| State | Role |
|-------|------|
| `ALEStart`       | start state |
| `VarAfter`       | after a variable token |
| `AleEgAfter`     | core "after operand / expecting operand" hub |
| `OperatWait`     | waiting for an operator after an operand |
| `EgAleWait2`     | after a `Mk` (marker) at start |
| `EgVectProcess`  | inside a vector/list element list |
| `EgVectProcess2` | after a vector element, expecting `,` or `=` |
| `FuncAfter`      | after a function name |
| `VectAfter`      | after a vector token (from start) |
| `VectAfter2`     | after a vector operand (from hub) |
| `EqAfter`        | after `=` (assignment RHS) |
| `EqAfter2`       | after `Mk Var` on assignment RHS |
| `End`            | accepting / terminal (two terminal shapes: 22 and 61) |

Legend shape (floating, unconnected) lists the terminator/delimiter tokens:
`"`  `,`  `)`  `]`  `}`  `:`  `..`  `then`  `else`

## Transitions (source --token--> target)

```
ALEStart
    Mk                  -> EgAleWait2
    Var                 -> VarAfter
    Vect                -> VectAfter

VarAfter
    ++, --              -> End
    =, Operator=        -> AleEgAfter
    ,                   -> EgVectProcess

AleEgAfter                       (central operand hub)
    Var, Const, Vect    -> OperatWait
    (, {                -> AleEgAfter   (self-loop: open nested sub-expression)
    Func                -> FuncAfter
    Vect                -> VectAfter2

OperatWait
    Operator            -> AleEgAfter
    Else ++, -- (векторные)  -> End

EgAleWait2
    ,                   -> EgVectProcess
    =                   -> EqAfter

EgVectProcess
    Mk, Var             -> EgVectProcess2

EgVectProcess2
    ,                   -> EgVectProcess        (loop: next vector element)
    =                   -> AleEgAfter

FuncAfter
    (                   -> AleEgAfter
    Var, Const, Vect    -> OperatWait

VectAfter
    [                   -> AleEgAfter
    ++, --              -> End

VectAfter2
    Operator            -> AleEgAfter
    [                   -> AleEgAfter

EqAfter
    Mk Var              -> EqAfter2
    Else                -> AleEgAfter

EqAfter2
    =                   -> EqAfter              (loop: chained assignment)
    Else                -> AleEgAfter
```

## Notes / observations

- `AleEgAfter` is the recursion hub: function calls (`Func (`), vector
  indexing (`Vect [`), and operator chains all route back through it.
- Two distinct `End` terminal shapes exist (IDs 22 and 61); they are
  semantically the same accept state.
- The `(, {` transition out of `AleEgAfter` has no glued `EndX` target in
  the `.vsdx`, but its endpoint coordinates `(4.43, 6.575)` fall *inside
  AleEgAfter's own box* (and Begin is on the same box). It's a short stub,
  i.e. a **self-loop on AleEgAfter**: `(`/`{` opens a nested sub-expression,
  which is itself an ALE and so re-enters the same operand hub.
- `EgVectProcess`/`EgVectProcess2` form the comma-separated vector/list
  element loop; `EqAfter`/`EqAfter2` form the chained-assignment loop.
